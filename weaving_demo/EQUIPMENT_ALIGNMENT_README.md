# 整经织造排工排产可视化 Demo — 设备编号数据对齐（整经/织造/水洗）

> 范围：只做 **整经、织造、水洗 三大流程的设备编号数据对齐**（设备主档、编号归一、
> 别名映射、任务→设备 关联、数据对齐报告）。
> **不做**：算法诊断、后整排程开发、甘特图交互改动（本轮明确排除）。整经机主档缺失按
> 「数据缺口」如实标注，**不虚构整经机编号**，也不把 整经机/织机/水洗机 混为一类。

## 一、数据来源

源文件：`副本【作成中整经织造】益丰生产管理表单260604.xlsx`

| 流程 | 设备 | 现场编号 | 系统主键 | 主档来源表 | 任务/引用表 |
|---|---|---|---|---|---|
| 织造 | 织机 | `#301` … | `LOOM-301` | ②织机状态（108 台） | 织造计划、落布预测、整经计划、水洗落布 |
| 水洗 | 水洗机 | `1号水洗机` | `WASH-01` | 水洗计划(每天)/水洗效率 表头 | 水洗计划(每天) 数据行 |

## 二、核心发现与对齐结论

1. **织造（织机）**：可从 `②织机状态` 唯一确定 108 台织机，编号均为 `#N` 形态（区域1~9，
   共 `#101…#912`）。用 `织造计划` 回填产能（米/天）与当前状态。编号归一后全部可溯源到
   `LOOM-###`。
2. **水洗（水洗机）**：全表**仅找到一台** `1号水洗机`（出现在 `水洗计划(每天)` / `水洗效率`
   表头）。系统主键 `WASH-01`。水洗计划数据行即该机台的排程行，全部关联到 `WASH-01`。
3. **整经（整经机）**：源表 `整经计划` / `整经预测辅助表` 中，**设备列被标注为「织机」**，
   单元格值是 `#301…#602` 等**目标织机号**（是织机主档的子集）。全表**没有**「整经机/整经N号机」
   编号（已对全部单元格做关键字扫描，仅命中 `1号水洗机`）。

   → 因此 **整经机主档为空（0 台）**；整经任务**无法唯一确定执行机台**，
   处理为：`equipment_id=""`、`assignment_status="待确认"`，并记录其**目标织机**（`LOOM-###`）
   作为人工确认线索。这是如实标注，而非虚构。

   > **口径更正（见 `WARPING_README.md`）**：整经任务不应按上半部分 60 行计，而应按
   > 「整经计划下半部分 + 整经预测辅助表」的 **经轴品番 × 日期** 计（本数据集为 5 个整经任务）。
   > 经轴品番（WP/WN）是经轴规格 SKU，织造品番（RP/RN）是织造半成品，整经机编号缺失保持待补充。

## 六、对齐规则（硬约束）

1. 不修改原始 Excel；不删除原表编号；保留 `source_code / source_value / source_cell` 可溯源。
2. 空白 / `0` / `NULL` / `#N/A` 不当作真实设备。
3. 不虚构现场编号：`id_source` 仅允许「来源表（…）」或「规则生成（并注明原因）」。
4. 整经机 / 织机 / 水洗机 分属不同 `equipment_type`，绝不混为一体。
5. 编号归一：去 `#` / 中文「号/机」后缀 / 全半角 / 文本与数字两种形态统一。
   例：`#101 / 101 / 101# / 织机101` → `LOOM-101`；`1号水洗机 / 1#水洗机` → `WASH-01`。
6. 设备无法确定 → `equipment_id=""`、`assignment_status="待确认"`，并给出 `reason/source`。
